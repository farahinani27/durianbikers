This page is a stand-in for a live Durian Bikers page. Only the chat widget in the bottom-right corner is real code — everything else is scaffolding so the widget can be judged in context.

Why this page exists

There is no local WordPress install and no staging sandbox, so this file is the safe way to review the chat widget. The network layer is stubbed: every request the widget makes is answered locally by the script at the bottom of this file. Nothing is sent anywhere.

How to use it

Pick an answer from the “Canned reply to send next” dropdown on the left, then send any message at all in the chat window — the reply you picked is what comes back. Your wording is ignored, so this page cannot tell you whether the assistant would understand a question; it only shows you how an answer looks and behaves. Every reply inside the window carries a dashed amber tag saying so. Those tags exist only in this preview and will not appear on the live site.

What to look at first

The "fitment question, declined" scenario. The catalogue has no structured bike-model data, so the assistant cannot confirm what fits what. That reply is the one worth reading closely before this goes live — a confident wrong answer on a brake or safety part is the expensive failure, not an unhelpful one. The "listed but unavailable to order" scenario is the second one to check: it covers the zero-variation imports, which are a large slice of the catalogue.

The shipping scenario. “Do you ship to Sabah / to Singapore?” is a question customers really ask. The assistant now answers it from the store's own Delivery Information page and shows a tappable link to that page underneath the reply, so the customer can read the policy in full. Judge the wording. The page links are the one thing on this mock that really will open the live site if you click them.

The WhatsApp handoff

At the bottom of the chat window, under the message box, there is a quiet row with a WhatsApp button, your opening hours and a line saying whether you are open. It is meant to be an escape hatch, not an advert — it should be easy to find when someone wants it and easy to ignore when they do not. Use the “WhatsApp handoff config” dropdown on the left to see all four states: open, closed, unknown, and not configured. In the last one the whole row disappears — no button, no line, no leftover gap.

Pick the “declined, hands over to WhatsApp” reply to see what happens when the assistant gives up and points at the button: the row lights up green for about six seconds, then goes quiet again.

What the message says when it opens. The link carries your customer's own last message so they do not have to type it twice — nothing else. Not the assistant's replies, not the products it showed. And if orders came up at all in the conversation, it carries nothing but a plain “Hi, I have a question from your website”: a WhatsApp link is saved in the browser's history and visible to the phone, and order numbers do not belong there. The control panel on the left shows the exact link at all times, so you can read it yourself — try the “order status” reply and watch the link fall back to the plain opener.

What else to look at

Open the launcher. Check that it clears the back-to-top button and the sticky header cart. Press Tab repeatedly with the panel open — focus should stay inside the panel. Press Esc — the panel should close and focus should return to the launcher. Then work through the scenarios in the control panel on the left, especially the error states and the XSS probe.

Responsive

At 375px the panel becomes a full-screen sheet over a dimmed overlay, and tapping the overlay closes it. At 768px and 1440px it is a floating panel anchored bottom-right.

Filler

Scroll content so the sticky header, the back-to-top button and the mobile scroll lock can all be observed. When the panel is open on a narrow viewport, the page behind must not scroll, and closing must return you to the same scroll position.
